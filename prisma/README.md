# Prisma Directory

This directory contains the database schema and migration files for the application. The schema is managed using [Prisma](https://www.prisma.io/), a modern ORM for Node.js and TypeScript.

## Purpose

The `prisma` directory serves as the single source of truth for the application's data model. It defines the tables, relationships, and constraints for the underlying PostgreSQL database.

## Tech Stack

* **ORM:** Prisma Client
* **Database:** PostgreSQL

## Key Components

* **`schema.prisma`**: The primary configuration file containing the Prisma data model definitions and database connection settings.
* **`migrations/`**: A directory containing SQL migration files generated by Prisma. These files track schema changes over time and ensure database consistency across different environments.
* **`dev.db`**: A local database file (likely used for local testing or a remnant of a previous SQLite setup, though the current schema is configured for PostgreSQL).

## Data Model Overview

The database schema models a comprehensive meeting and webinar platform, covering the following key domains:

* **Users & Teams:** `User`, `Team`, `TeamMember`, `TeamInvite` - Handles user accounts, team organizations, roles, and invitations.
* **Meetings & Rooms:** `Room`, `MeetingSession`, `MeetingInvite` - Defines persistent rooms, individual meeting sessions, and access controls. Rooms support configurations like waiting rooms, PIN access, and distinct modes (meeting/webinar).
* **Communication & Engagement:** `ChatMessage`, `MeetingQA`, `MeetingPoll`, `SharedNote` - Supports real-time collaboration, Q&A, and interactions within meetings.
* **Media & Recording:** `Recording`, `LiveStream` - Manages recordings of meetings and multi-platform external RTMP live streams.
* **AI & Content:** `Transcription`, `MeetingSummary` - Stores automated meeting transcriptions and AI-generated action items and summaries.
* **Telephony:** `DialInNumber`, `CallDetailRecord` - Supports dial-in access for meetings and tracks call details.
* **Monetization & Plans:** `Plan`, `Subscription`, `PaymentTransaction` - Handles subscription plans and payment processing for paid features, paid recordings, and donations.

## Working with Prisma

### Prerequisites

Ensure you have a PostgreSQL database running and the `DATABASE_URL` environment variable properly configured in your `.env` file at the root of the project.

```env
DATABASE_URL="postgresql://user:password@localhost:5432/yourdatabase?schema=public"
```

### Common Commands

* **Generate Prisma Client:**
  Generates the TypeScript client based on the current schema. You need to run this after pulling new changes or modifying the schema.
  ```bash
  npx prisma generate
  ```

* **Apply Migrations (Development):**
  Applies existing migrations to your development database and creates a new migration if the `schema.prisma` has changed.
  ```bash
  npx prisma migrate dev --name <migration_name>
  ```

* **Apply Migrations (Production):**
  Applies any pending migrations. Use this in production or CI/CD environments.
  ```bash
  npx prisma migrate deploy
  ```

* **Open Prisma Studio:**
  Opens a local web-based GUI to view, query, and edit data in your database.
  ```bash
  npx prisma studio
  ```

### Modifying the Schema

1. Update the `schema.prisma` file with your new models, fields, or relationships.
2. Run `npx prisma migrate dev --name describe_your_change` to create and apply a migration.
3. The Prisma Client will automatically regenerate.
4. Update your application code (and any affected tests) to reflect the new schema structure.
